# Azure Hillclimber [Reducing agent construction to an optimization problem]

## What is it?

A method of automatically building **role-specialized agents**. Inspired by traditional machine
learning methods, this process leverages Github Copilot as a **'master agent'**. Unstructured data
describing a problem statement is transformed into a labeled training dataset, which is then used by
GHCP to iteratively build agents.

Each iteration involves a cycle of "Data Experiment, Build, Deploy, Test, Evaluate, Refine". Over
successive iterations, the agent converges to a plateau based on the dataset provided.
**Effectively reducing agent construction to an optimization problem.**

![Autonomous Agent Loop: define data and objective, let AI handle the build](/assets/loop-understand-build-evaluate.png)

The output of this process is an agent which performs well given dataset conditions, as well as an
application with tooling and features designed to facilitate the agent's good performance of the
specific task.

The interaction between the application and the agent is as crucial as the ability of the agent to
use its tools to perform a task; as such, this method is particularly well suited for
**PoC creation**, and is able to deliver quick and promising results **when datasets are properly
specified and the domain is not unconstrained**.

:::tip[The core insight]
Instead of tuning model parameters, you edit tools, configuration files, prompts, API interfaces,
application capabilities, etc... Which reduces optimization to a coding task.

As coding is currently the primary targeted domain for progressing LLM competency, this approach is
likely to provide long term benefits.
:::

## Why It Matters

This method helps to begin **formalizing the hill-climbing concept as a consistent methodology**
rather than a set of disconnected, one-off methods.

A key source of leverage is that this methodology exploits synergistic advantages native to the
Microsoft stack, enabling rapid development and testing, as well as facilitating a model of
iterative improvement:

1. **End-to-End Coverage** — Development tooling (GHCP), data foundation (MSIQ), identity management
   (Entra), ML/LLM (Foundry), along with a feature-complete cloud stack (Azure), covering complete
   requirements of any potential AI solution natively.
2. **Infrastructural changes and data updates accompany alterations to agents.** GHCP is able to use
   Azure CLI to materialize code changes, and vice-versa. This significantly streamlines the
   deployment process, speeds up solution deployment, and reduces orchestration complexity.
3. **Centralized policy-driven management** simplifies governance.
4. **O365 usage history and integration** provides ready made data source for analytics,
   investigation, and working profile incorporation.

## Core Components

1. **An application framework**, which GHCP can use to directly control or pilot an agent via API
   call and console commands.
2. **A testing/evaluation framework**, for assessing agent performance and producing a set of
   quantifiable, evidence-based metrics.
3. **A data processing framework**, for capturing key lessons about the data through iterative
   experimentation.
4. **A development framework**, used to accelerate development by reducing the cognitive load of the
   coding agent — GHCP should spend time on design, testing, and problem understanding. Not on
   generating boilerplate code snippets.
   - A standardized component library ie. A chat interface, Azure data connectors, DB CRUD tools,
     agent definition tooling, etc...
   - **Composable, configuration driven agent design** — for building agents by piecing together
     standardized tooling, prompts, and component designs. Minimizing coding work and maximizing
     effort spent on system design and testing.
   - A harness which promotes **autonomous long-form work**
     - Hooks for reinforcing system design and mandating codebase simplification, plus periodic
       review to prevent overengineering
     - Internal knowledge bases for tracking dependencies and prior work, minimizing waste
     - Issue trackers to capture specs, prevent premature stoppage, and control/document
       long-running development tasks — leveraging Github for agentic project management
     - Research tooling, to identify and retrieve existing internal or external capability, reducing
       unnecessary coding effort and preserving context for systems understanding
   - Comprehensive documentation to preserve system understanding and capture known pitfalls and
     Gotchas ie. **CosmosDB periodically disabling public network access**, necessitating private
     endpoint deployment (Otherwise leading to **six hours of unsuccessful autonomous debugging**)

## Dataset Preparation

The labeled dataset is the input the whole loop optimizes against, so it is worth seeing one built
end to end. [Dataset Preparation](/dataset-prep) takes a single page of a public AEMO incident
report and shows the full conversion: the page itself, the verbatim lines lifted from it, the four
label objects derived from those lines, and the pass/fail checks those labels become when the agent
runs.
