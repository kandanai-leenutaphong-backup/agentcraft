# The Method [One iteration. Repeat until the score stops moving.]

:::warning[Draft]
Step explanations are drafts and the diagrams are indicative. The cycle names are as authored.
:::

## 1. Data Experiment

Probe what the dataset actually supports before committing to a build. Cheap, discardable runs
establish the ceiling: which questions the data can answer, which it cannot, and where the labels
are ambiguous.

<Diagram name="experiment" />

## 2. Build

Assemble the agent from existing pieces: tools, prompts, configuration, application seams.
Composition, not authorship — writing new code is the fallback, not the default.

<Diagram name="build" />

## 3. Deploy

Ship into the real configured runtime, not a notebook. Infrastructure and data move with the agent,
so what is tested is what exists.

<Diagram name="deploy" />

## 4. Test

Run the agent against the labeled cases from step one. Every case passes or fails on its own terms;
a case that cannot fail proves nothing.

<Diagram name="test" />

## 5. Evaluate

Score the run and compare it with the one before. The number is the gradient: without it there is no
way to know whether the last edit helped.

<Diagram name="evaluate" />

## 6. Refine

Edit tools, configuration, prompts, interfaces, application capability. Not model weights. That is
what makes the loop a coding task, and what makes it repeatable.

<Diagram name="refine" />
