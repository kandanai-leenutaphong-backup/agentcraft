# Anonymized Cleanup Case Study

Historical case study, 2026-09-13. Names and paths are generalized; measurements are retained,
not invented or reproduced here. Original receipt fingerprints are not distributed. These
paths are not a deletion policy for another project.
The user requested aggressive filesystem cleanup after preserving a completed optimization campaign.

The research deletion groups spanned 14 catalog sections. Largest file-count contributors were
vulnerability/advisory mirrors (1,165,341 files) and supply-chain/SBOM mirrors (245,455).
Examples include CVE List v5, GitHub Advisory Database, CISA Vulnrichment, Ubuntu Security
Notices and OpenSSF Malicious Packages. Their catalog presence did not establish a runtime consumer.
Required normalization sources and acquired dataset folders were excluded explicitly.

The anonymized catalogue records groups, not every individual file name: no per-file deletion
inventory was captured during the original cull. Do not fabricate one from later directory state.
The companion JSON catalogue retains each group's count, reason, retention decisions, grouped
research totals and historical verification statements. Source-receipt digests are omitted.
It contains no downloaded payloads and grants no permission to repeat these deletions elsewhere.

## What Stayed

- All application source, security controls, tests, active frontend dependencies and project Python packages.
- Canonical example/evaluation inputs and prepared outputs, normalized corpora and nine acquired dataset folders.
- Six pinned corpus sources: Atomic Red Team, ATT&CK STIX, Azure Sentinel content, SigmaHQ,
  GuardSight and VERIS. Source selectors, not directory names, established retention.
- Acquired Splunk LFS telemetry and the `motif` mirror with local modifications. Of 118 nested
  Git repositories inspected among candidates, that modified checkout was excluded.
- All accepted and earlier experiment ledgers, proof reports and the final 1,553-file reproduction bundle.
- The existing virtual environment, because its selected-editor usage had not been established.
- Current harness instructions and `docs/notebook/`. The active notebook replaced obsolete routing;
  this was not a ban on documentation or durable knowledge.

No Git object store, cloud resource, authentication setting or canonical dataset was deleted.

## Recovery

The three named small legacy/reference trees were packed into one private archive outside the
workspace and checked against the original files before deletion. Tracked history also remained.
The research-resource records retained source provenance outside the workspace, not full payload
backups. Removed research payloads require reacquisition, which may not reproduce the same revision.
The retained final optimization bundle was verified against its previously recorded SHA-256.

Net reduction: **1,590,489 files (96.01%) and 68,833,614,028 logical bytes**. Planned removal
contained 1,590,495 files; regenerated checks and new records account for the net difference.
These are the recorded post-check counters, before later note publication, not a current-tree promise.
Logical bytes are not allocated disk blocks or RAM released. No process-memory benchmark was taken.

## Checks That Closed the Work

- Complete saved-campaign audit: 28 retained completed attempts, 100,212 outcomes, 56 genuine
  examples and unchanged original baseline hashes. Recorded errors remained, not pruned.
- Both knowledge builders ran in dry-run mode: 9,471 documents and 959 situation types from
  retained sources, with no normalized output rewritten.
- A real evaluation case cache regenerated byte-identically after deletion in a temporary directory;
  its seven evidence rows exposed only evidence and training profiles, never a label table.
- Focused optimizer tests: six tests and five subtests passed; an existing deprecation warning remained.
- Frontend production build passed; its existing large-chunk warning remained.
- Saved-results browser replay passed 28 checks, including desktop/mobile 13-point plots,
  real replays, catalogue navigation and terminal-key revocation. No model campaign was rerun.
- Architecture: 1,833 files scanned, zero declared violations, 11 unresolved imports and
  55 unowned source files reported honestly. Previous broad scans included removed mirrors/copies.
- All protected evaluation/bundle hashes matched; 81 maintained documents had no broken Markdown links.

## Recurrence Prevention

Narrow VS Code watcher/search exclusions covered raw data, generated state and installed
dependencies without hiding app source. Test/search configuration excluded generated restore trees.
New screenshots and restore-check defaults moved outside the repository. Active instructions,
ownership declarations, current docs and provenance wording stopped pointing to retired paths.
Public component and ontology edits were documentation-only; scored optimizer behavior stayed fixed.

## Portable Lessons

Measure ignored files first: most weight was not application code. Preserve source selectors and
data provenance, not arbitrary mirror collections. Verify the one trusted preservation package
before deleting its expanded trial copies. A cache is disposable only after its regeneration path
is proven. Check nested worktrees and active writers. Treat history, tests, backups and raw data
according to their ownership, not according to whether the frontend imports them.
