# Signed Dev Access

Install `signed-dev-access`; import `signed_dev_access`. Native skill name and
triggers remain, but `devauth` and skill-local scripts are retired. The
[server contract](../../src/signed_dev_access/README.md) owns the existing verifier,
middleware and replay ledger. No duplicate verifier, replay cache or auth bypass
was migrated. [Historical findings](historical-findings.md) distinguish retained
safety from corrected or retired recipes.

## Public Client API

| Surface | Contract |
| --- | --- |
| `sign_headers(private_key, method, path_and_query, body=b"", context_slug="", *, timestamp=None)` | In-memory signature headers from canonical bytes; caller owns destination and grant |
| `load_private_key(absolute_path)` | Explicit bounded raw-Ed25519 file read; no discovery, generation or writes |
| `RequestSigner(private_key, *, origin, context_slug="", allow_loopback_http=False, allow_mutations=False, clock=None)` | One trusted origin and client policy; construction performs no HTTP |
| `signer.headers_for(method, url, body=b"", *, headers=None)` | Fresh signature for the exact origin; signing headers positively stripped from foreign origins |
| `signer.request(method, path_and_query, body=b"", *, content_type="application/octet-stream", timeout_seconds=30, max_response_bytes=1048576, connection_factory=None)` | One native request, redirects refused, bounded `SignedResponse`, no output or retry |
| `SignedResponse(status, body)` / `.metadata()` | Response body is explicit API data and omitted from repr; metadata contains only status and byte count |
| `SigningError.code` | Stable payload-free refusal/failure code; no raw key, URL, response or exception text |
| `request_body(cdp_request)` / `BodyNotSignable` | Exact bounded binary body from CDP base64 entries; never a lossy text fallback |
| `install_request_signing(context, *, signer, should_sign=None)` | Borrowed Chromium context; returns a closeable `BrowserSigning` handle |
| `new_piloted_context(browser, *, signer, should_sign=None, **options)` | Fresh owned Chromium context with service workers blocked; returns a context-manager handle whose `.context` is the browser context |

Headers returned by Python APIs are transient authentication material for the
request transport, not log/console/artifact data. Never store them in static
browser headers, HAR, protocol traces or test reports. Browser signing intercepts
each redirect leg using CDP, not `route.continue_` or buffered `route.fetch`.
Responses remain in the browser network stack; no response body is buffered by
the interceptor. Narrowing predicates must return an actual boolean.

## Private State And Authority

No private key is generated by import, installation, CLI help or a default path.
Key provisioning/rotation remains an explicitly authorized operator/secret-store
workflow. Never put private keys in a repository, image, command argument, response
body or output. The server receives only its separately configured public verifier.
Clearing that public key disables mounting; the primary auth path remains intact.

The file loader requires an absolute, non-symlink path, a caller-owned private
directory (no group/other permissions), a caller-owned regular file of exactly
32 bytes, mode 0400 or 0600 and one hard link. It refuses detected Git/Hg/SVN
ancestors, traversal, malformed keys and unsafe files. Directory/file descriptors
use no-follow access; private values never appear in error messages. These POSIX
checks are not encrypted storage, memory zeroization or proof that an unmarked
directory is not project data; the host still selects a private state location.

HTTPS is required; unencrypted HTTP needs explicit opt-in and is limited to
loopback. Origin means exact scheme, lowercased host and effective port, with no
userinfo, path prefix, query or fragment. Requests cannot change that binding.
Methods beyond GET/HEAD/OPTIONS require `allow_mutations=True` on the bound signer;
this client setting does not grant application, model or Azure permissions.

## CLI

```bash
python -m signed_dev_access request GET /api/status \
  --origin https://app.example.invalid --key-file /operator/private/signing-key
```

Without `--send`, this prints only `{"sent": false}` and performs no key read or
request. After explicit authorization, add `--send`. Body input is explicit
`--body-file` or `--body-stdin`; the private key file itself is refused as a body.
Mutating methods also require `--allow-mutation`. The CLI never prints response
bodies or signing headers. HTTP outcomes print status/response byte count;
validation/transport failures print a safe code. Exit 0: dry run or 2xx; exit 1:
non-2xx; exit 2: input, policy, redirect or transport refusal/failure.

Retired commands: `init`, forced key overwrite, ambient key/URL lookup, `pubkey`
printing, `sign` header dumping and unbounded response streaming to stdout.
Use in-memory public-key derivation at the authorized host if needed; this change
creates no operational credential or deployment.

## Bounds, Failures And Lifecycle

Canonical path bound: 8,192 characters; context input: 128 characters and normalized
slug `[a-z0-9_-]{0,64}`. Method: 1-32 ASCII letters. Raw path/query must be ASCII,
origin-relative and well-formed percent encoding, without controls, whitespace,
fragment, backslash or an empty query delimiter. Body: at most 1 MiB. Signed bytes
are never decoded or reserialized. Concurrent bound-signer timestamps advance by
microseconds; a stalled/backward clock cannot widen the fixed server skew.

HTTP defaults: 30-second socket timeout and deadline checked between bounded
response reads, maximum timeout 300 seconds; default response cap 1 MiB, maximum
16 MiB. DNS/native blocking header parsing are not a hard whole-operation deadline.
There are no redirects, environment proxy selection, debug output or automatic
retries. Error/redirect bodies are not consumed. A failure after submission may
have effects; `request_failed` or cancellation does not prove rollback.
Every request closes its owned connection on success/failure. An injected factory
must create an owned connection per call; it is not a borrowed-client parameter.

Client error codes distinguish invalid input, `mutation_not_authorized`,
`https_required`, private-file refusal, `redirect_refused`, `response_limit`,
`request_timeout`, `request_failed` and `close_failed`. Server authentication
failures remain the same empty private/no-store 401 with no diagnostics or logs.
Clients must not parse provider messages or equate non-2xx with unchanged state.

Browser body capture allows at most 4,096 base64 entries and 1 MiB decoded bytes.
Missing/invalid entries abort the paused request and expose only `body_not_signable`.
A pilot holds at most 64 page sessions. It re-signs trusted redirects, strips
foreign signing headers, attaches caller-created pages before they can navigate,
and reports only bounded error codes/counters. `close()` restores hooks and
detaches sessions once; it closes an owned context, never a borrowed one.

Use a fresh unrecorded Chromium context. `new_piloted_context` refuses service-worker
enablement, HAR recording and inherited storage/basic-auth state. Do not add
Playwright protocol logging, tracing, static signing headers or competing
`context.route` handlers externally. App-opened popups can have an unsigned first
navigation; cross-origin out-of-process frames are not covered. Host auth must
refuse those unsigned requests. These limits are not bypasses or hidden fallbacks.

## Server Safety And Verification

The host still provides public key, identity factory, mandatory replay ledger and
one authorization gate. Signatures establish a separate agent identity, never an
implicit production-user or administrator identity. Replay keys hash decoded
signature bytes; retention lasts until signed timestamp plus 300 seconds, including
future-dated signatures. Full/unavailable ledgers deny. Cross-replica defense needs
the host's shared ledger; a process-local ledger is not sufficient evidence.
